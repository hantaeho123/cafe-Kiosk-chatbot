# 공차 키오스크 데이터

"RAG: 카페 Kiosk 자연어 인터페이스" 과제용 데이터. 시연 매장은 **공차 시흥배곧점**, 수집일은 **2026-10-12**.

## 폴더 구조

| 경로 | 내용 | 만든 방법 |
|---|---|---|
| `raw/official/` | 공식 홈페이지 원본 (메뉴 176종, 안내 페이지, 신메뉴 포스터, 매장) | `scripts/scrape_official.py` |
| `raw/baemin/prices.csv` | 배민 캡처에서 옮겨 적은 배달가·추천 당도·얼음 고정 여부 (140행, 91개 메뉴). 가격은 쓰지 않고 추천 당도·얼음·인기 순위만 가져온다 | 캡처를 보고 직접 입력 |
| `raw/store/prices.csv` | **매장 판매가** (204행). 키오스크가 쓰는 가격은 모두 여기서 온다. `source` 열: 매장 메뉴판 사진(`menu_board`, 음료 115행), 키오스크 화면 사진(`kiosk_food` 등). 다이닝코드 시흥배곧점 메뉴정보(`diningcode`, 음료 51행·푸드 17행)는 갱신일을 알 수 없어 대조용으로만 적어 두고 쓰지 않는다. 공식 메뉴 데이터에 없는 상품(미피 MD, 펄볶이 세트, 밀크티 아포가토)도 적어만 두었다. 사진은 `raw/store/screenshots/` | 사진·페이지를 보고 직접 입력 |
| `raw/baemin/screenshots/` | 가격 캡처 원본 3장 | 사용자 제공 |
| `curated/` | 옵션·정책·키오스크 흐름·이용 안내. 항목마다 `verified`, `source` 표기 | 직접 정리 |
| `curated/barcodes.json` | **시연용** 바코드(멤버십·앱·쿠폰·교환권·금액권·결제)와 결제 단말기 시나리오. 실제 바코드와 무관하게 지어낸 값 | 직접 작성 |
| `curated/stock.json` | 서버를 켰을 때의 품절 상태(시연용 초깃값) | 직접 작성 |
| `images/` | 상품 사진 176장 (`{공식 상품번호}.png`) | `scrape_official.py --images` |
| `kiosk/` | **웹 키오스크가 읽는 최종 데이터** | `scripts/build_dataset.py` |
| `rag/documents.jsonl` | **RAG 검색용 문서 238개** | `scripts/build_dataset.py` |
| `rag/index/` | 문서 임베딩으로 만든 FAISS 인덱스 (git 에 올리지 않음) | `scripts/build_index.py` |

`kiosk/` 와 `rag/` 는 손으로 고치지 않는다. `raw/`, `curated/` 를 고친 뒤 다시 빌드한다.

```bash
python3 scripts/scrape_official.py --images   # 공식 사이트 다시 수집 (약 2분)
python3 scripts/build_dataset.py              # kiosk/, rag/ 다시 생성
```

## kiosk/menu.json

`items[]` 한 개가 메뉴 하나다 (음료 120, 푸드 41, MD 14).

| 필드 | 설명 |
|---|---|
| `id`, `official_no` | `drink-53` 형식의 ID, 공식 사이트 상품 번호 |
| `name`, `aliases`, `description` | 공식 메뉴명, 배민 표기(띄어쓰기가 다름), 공식 설명 |
| `category` | 밀크티 / 스무디 / 오리지널 티 / 프룻티&모어 / 커피 / 요거티 (푸드는 베이커리·스낵·아이스크림) |
| `series`, `is_new_season`, `is_best_seller`, `badges` | 시리즈 묶음, 시즌·베스트셀러 여부, 배민 인기 순위·사장님추천 |
| `on_sale`, `sizes[]` | 시연 매장 판매 여부, 사이즈별 가격과 용량(ml) |
| `temperatures` | `["ICE","HOT"]` 또는 `["ICE"]` |
| `options` | 당도·얼음 조절 가능 여부와 추천 당도. `source` 가 `baemin` 이면 캡처에서 확인, `inferred` 면 추정, `null` 이면 미확인 |
| `included_toppings` | 메뉴명에 들어 있는 기본 토핑 |
| `nutrition[]`, `allergens` | 공식 영양정보(온도·사이즈별)와 알레르기 유발물질. 커피는 `variant` 로 ESP/DRIP 구분 |
| `tags` | 추천용 파생 값 (베이스 티, 맛 특징, 카페인 수준 등). **공식 값이 아니라 메뉴명·설명에서 규칙으로 뽑은 것** |
| `image`, `image_url`, `source_url` | 로컬 사진 경로, 원본 주소, 출처 |

## rag/documents.jsonl

한 줄에 `{id, type, title, text, metadata, source}`. `text` 를 임베딩하고 `metadata` 로 필터링한다.

| type | 개수 | 내용 |
|---|---|---|
| `menu` | 175 | 메뉴별 설명·가격·옵션·영양정보·알레르기 |
| `recommendation` | 20 | 맛 특징별, 인기 순위, 무카페인, 저칼로리, HOT 가능, 우유 없는 음료, 신메뉴·시즌, 곁들일 디저트 등 |
| `option` | 14 | 당도와 단계별 뜻, 얼음량(고를 수 없는 "얼음 없이" 포함), 토핑 종류·가격, 사이즈, HOT/ICE, 컵 |
| `category` | 9 | 카테고리별 메뉴판 |
| `policy` | 6 | 멤버십, SKT, KT, 카카오페이, 페이코, 고객센터 |
| `knowledge` | 5 | 찻잎 4종 설명, 브랜드 소개 |
| `guide` | 8 | 주문 방법, 키오스크 사용법, 결제 방법과 단말기 위치, 적립·할인·쿠폰, 교환권·금액권, 요청 사항 처리 방침, 직원 호출 방법, 알레르기 안내 |
| `store` | 1 | 매장 정보 |

품절 여부, 지금 장바구니, 가격 계산 결과는 문서가 아니다. 키오스크가 대화할 때마다 실시간 값으로 넘긴다(`app/chatbot/prompts.py` 의 `<실시간상태>`).

## 꼭 알아야 할 한계

1. **가격은 매장 판매가이고, 매장 메뉴판·키오스크 화면 사진에 있는 메뉴만 판다.** 다이닝코드 매장 메뉴정보는 갱신일이 표시되지 않고 지난 시즌 메뉴(수박·참외 등)와 1리터 배달 메뉴가 섞여 있어 가격으로 쓰지 않았다. 확인한 모든 칸에서 매장가 = 배달가 − 300원이었지만(메뉴판 105칸, 다이닝코드 35칸), 배달가에서 빼서 계산한 값은 넣지 않았다.
2. **사진에 없는 메뉴는 숨긴다.** 음료 120종 중 76종만 판다. 나머지 44종(저당 시리즈, 납작복숭아 아이스티, 수박·참외·밤·쑥·애플 시즌 메뉴, 1리터 배달 메뉴 등)은 메뉴판·대화 카드에 나오지 않는다(`on_sale: false`). 푸드는 41종 중 키오스크 화면 사진에 있는 12종만 보여 주고, MD 14종은 가격이 없어 모두 숨긴다. 숨긴 메뉴도 RAG 문서는 남아 있어 물어보면 "가격 미확인"으로 답한다. 푸드는 가격을 알아도 키오스크 주문 대상이 아니다(카운터 주문으로 안내).
3. **영양정보는 당도 0% 기준이다** (스무디는 당도 고정). 당도를 올리면 실제 당류·열량은 더 높다.
4. **메뉴판 사진의 촬영 시점은 확인되지 않았다.** 다이닝코드 값과 겹치는 칸은 모두 같았다.
5. **HOT 가격은 ICE 와 같다고 가정했다.** 캡처에는 온도별 가격 구분이 없다.
6. **토핑 가격은 사이즈마다 다르다** (`curated/options.json` 의 `price_by_size`). 매장 메뉴판 기준 L 은 펄 600·미니펄·화이트펄·알로에·코코넛·밀크폼 700·치즈폼 900원, J 는 각각 200원 더 비싸다. 샷 추가는 500원으로 같다. 토핑 L 가격은 배민 '공차슈페너' 옵션 화면과도 같았다.
7. **파는 메뉴 중 당도·얼음 조절 여부를 모르는 메뉴가 8종 있다** (`options.source: null`). 배민 목록에 없거나 추천 문구 대신 설명이 나온 메뉴들이다.
8. **제로 피치 우롱 아이스티 + 알로에**는 배민에서 J 사이즈인데 공식 영양표에는 L·G 만 있다.
9. **카카오페이 프로모션은 종료된 것으로 보인다** (공식 페이지 기간 표기가 2025년 12월까지).
10. **메뉴의 외국어 이름과 설명(`i18n`, `name_en`)은 번역한 값이다.** 공식 사이트에 없어서 `scripts/translate_menu.py` 로 영어·중국어·일본어로 번역했다(`curated/menu_i18n.json`). 영문명의 눈에 띄는 오역만 손으로 고쳤고 전체를 검수하지는 않았다. 파일을 직접 고치면 다시 번역해도 그 값이 유지된다.
11. **신메뉴 페이지는 포스터 이미지뿐이라 판매 기간 텍스트가 없다.** 이미지 주소만 `raw/official/new_menus.json` 에 있다.

12. **이용 안내 문서(`guide:*`)의 화면 흐름과 기기 위치는 가정값이다.** 이 프로젝트의 키오스크 화면에 맞춰 쓴 것이고, 결제 단말기·카드 투입구·바코드 리더의 위치는 일반적인 키오스크 구성을 가정했다.
13. **당도 단계별 설명은 공식 문구가 아니다.** 공식 페이지에는 "5가지 당도"만 있어, % 의 일반적인 뜻(기본 레시피 대비 시럽 양)을 풀어 썼다.
14. **교차 오염 안내와 밀크폼·치즈폼의 우유 성분은 공식 표기가 아니다.** 알레르기를 단정하지 않기 위한 일반 안내와 재료로 추정한 값이다.

## 매장에서 확인해야 할 것 (`curated/` 의 `verified: false`)

- 얼음량 단계 (최종 HTI 를 따라 적게·보통·많이로 두었다. 보통·적게만 확인했고 많이는 미확인. "얼음 없이"는 고를 수 없는 값으로 두고 요청 메모로 넘긴다)
- 키오스크 결제 수단, 지원 언어, 매장/포장 선택 화면, 영수증·주문번호 방식
- 결제 단말기·카드 투입구·바코드 리더·영수증 출구의 위치
- 컵 종류별 규칙(매장컵·일회용컵·개인컵)과 개인컵 할인 금액, 포장 옵션(빨대·캐리어)
- 요청 사항(메모)을 받는지와 처리 방침, 조작이 없을 때 처음 화면으로 돌아가는 시간
- 쿠폰 종류와 적용 규칙, 교환권·금액권 처리 방식 (지금 값은 모두 시연용)
- 멤버십 무료 쿠폰에 필요한 스탬프 개수
- 메뉴별 토핑 최대 개수 (공식 안내는 3개, 공차슈페너는 배민에서 1개)
