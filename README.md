# cafe-Kiosk-chatbot

공차(시흥배곧점) 메뉴로 만든 **카페 키오스크 자연어 인터페이스**. 손님은 화면 버튼으로도, 글로도 메뉴를 묻고 추천받고 주문한다.
RAG(검색 증강 생성)와 OpenAI Function Calling 으로 동작하며, 화면과 기능은 최종 HTI("메뉴 주문하기")를 따른다.

버튼은 그대로 두고 대화를 더한 하이브리드 키오스크다. **모델은 주문을 직접 바꾸지 못하고**(변경안을 올리면 손님이 눌러 확인), **결제는 손님이 화면과 단말기로 직접 한다.**

## 실행

Python 3.10 이상이 필요하다.

```bash
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt                      # uv 로 만든 .venv 라면: uv pip install -r requirements.txt
cp .env.example .env          # .env 를 열어 OPENAI_API_KEY 를 넣는다

python scripts/build_index.py # 문서 임베딩 → FAISS 인덱스 (처음 한 번, 생략해도 서버가 알아서 만든다)
python -m app                 # 키오스크 http://localhost:8000 · 직원 화면 http://localhost:8000/staff
```

- 화면 오른쪽 위의 **근거 보기**를 켜면 답변마다 검색된 문서(유사도)와 호출된 도구가 보인다. 시연할 때 켜 두면 좋다.
- **직원 화면**(`/staff`)을 다른 창에 띄워 두면 직원 호출, 결제된 주문과 요청 메모, 품절 처리를 볼 수 있다.
- 결제와 바코드는 시연용이다. 결제 화면의 "시연용 바코드", "어떤 카드를 꽂을까요?"에서 고른다.
- 조작이 없으면 2분 뒤 "시간 연장" 안내가 뜨고 30초 뒤 처음 화면으로 돌아간다. 발표 중에 방해되면 `.env` 에 `IDLE_SECONDS=0`.

```bash
python -m pytest                    # 테스트 (API 키 없이 돈다)
python scripts/eval_retrieval.py    # HTI 과업별 질문에 기대한 문서가 검색되는지 확인 (API 키 필요)
python scripts/eval_scenarios.py    # 실제 모델로 유스케이스 1~3 과 제약(G1~G9)을 돌려 과업별 통과 여부를 본다 (API 키 필요)
```

프롬프트나 도구를 고친 뒤에는 `eval_scenarios.py -n 3` 으로 다른 과업이 깨지지 않았는지 확인한다(모델 답은 매번 조금씩 달라서 여러 번 돌린다).
2026-10-13 기준 검색 평가는 38/38 이다. 시나리오 평가는 검사 51개를 두 번씩 돌려 102개 중 101개를 통과했다. 가끔 놓치는 것은 "둘 다 매장에서"를 함께 기록하는 것과 예산 추천에서 합계를 한 번에 말하는 것이다.

## 배포

Render 에 올린다. 설정은 `render.yaml` 에 있다. 대시보드의 New → Blueprint 에서 이 저장소를 고르고 `OPENAI_API_KEY` 를 입력한다.
다른 서버에 올릴 때도 같다: `pip install -r requirements.txt` 뒤 `HOST=0.0.0.0 python -m app` (포트는 `PORT`, 키는 `OPENAI_API_KEY` 환경 변수).

- 대화·주문·품절 상태가 서버 메모리에 있어서 **인스턴스(워커)는 하나만** 띄운다. 요청마다 다른 인스턴스가 받을 수 있는 서버리스 환경에는 맞지 않는다.
- Render 무료 플랜은 15분 동안 접속이 없으면 잠든다. 깨어날 때 RAG 인덱스를 다시 만들고(몇 초), 상태는 처음으로 돌아간다.
- 주소를 아는 사람은 누구나 이 서버의 OpenAI 키로 대화하고 직원 화면(`/staff`)도 열 수 있다. 환경 변수 `ACCESS_PASSWORD` 를 넣으면 키오스크와 직원 화면 모두 브라우저가 비밀번호를 묻는다(아이디는 아무거나). Render 에서는 대시보드의 Environment 에 추가한다.
- 대화는 손님 한 명이 10분에 40번, 서버 전체가 1시간에 600번까지만 받는다(`CHAT_LIMIT_PER_SESSION`, `CHAT_LIMIT_PER_HOUR`). 그래도 OpenAI 대시보드에서 월 사용 한도를 걸어 둔다.

**손님이 한마디 하면 (agent.py)**

1. **검색**: 손님의 말을 임베딩해 문서 6개를 찾는다. 동시에 Moderation 으로 유해한 입력인지 확인한다.
2. **증강**: 시스템 프롬프트 + 최근 대화 + `<실시간상태>`(품절·장바구니·확인 대기 중인 변경안·POS 금액·결제 상태·직전에 안내한 메뉴) `<화면조작>` `<참고문서>` `<손님>` 을 묶어 모델에게 보낸다.
3. **생성**: 모델이 답을 쓰거나 도구를 부른다. 도구 결과를 돌려주고 다시 묻기를 반복한다(최대 5번).
4. **검증**: 다 쓴 답변을 코드가 다시 본다(`checks.py`). 근거에 없는 금액이 있으면 모델에게 한 번 다시 쓰게 하고, 알레르기 질문이나 요청 메모에 꼭 들어가야 할 안내가 빠졌으면 정해 둔 문구를 붙인다.
5. 답변은 글자가 나오는 대로 화면에 흘려 보내고(SSE), 메뉴 카드·비교표·빠른 답변 버튼을 붙인다.
6. 모델이 주문을 바꾸는 도구를 불렀으면 **변경 확인 화면**이 뜬다. 손님이 [확인]을 눌러야 주문에 반영된다. 변경안이 기다리는 동안 손님이 "네"라고만 하면 모델을 부르지 않고 [확인]을 눌러 달라고 답하며 확인 화면을 다시 띄운다.

**주문을 바꾸는 두 가지 길**

| | 누가 | 어떻게 반영되나 |
|---|---|---|
| 버튼 | 손님이 메뉴판·옵션 화면·주문 내역에서 직접 | 바로 반영 (`/api/order/*`) |
| 대화 | 모델이 도구로 **변경안**(주문의 복사본)을 고침 | 변경 확인 화면에서 손님이 [확인]을 눌러야 반영 (`/api/order/confirm`) |

결제(`/api/pay/*`, `/api/scan`)는 버튼으로만 할 수 있다. 모델에게는 결제·할인·적립 도구가 없다.

**설계 원칙: 말은 모델이, 계산과 확정은 코드와 손님이.** 가격 합계, 할인, 옵션이 되는지 안 되는지는 `order.py`·`pos.py` 가 정한다.
모델은 도구 결과의 숫자를 그대로 읽어 줄 뿐이라 가격을 지어낼 수 없고, 손님이 누르지 않은 것은 주문이 되지 않는다.

## RAG

| 단계 | 구현 |
|---|---|
| LOAD | `data/rag/documents.jsonl` 236개 문서 (`scripts/build_dataset.py` 가 생성) |
| SPLIT | 따로 하지 않는다. 문서를 만들 때 이미 "메뉴 1개 = 문서 1개"로 나눴다 |
| EMBED | `text-embedding-3-small`. 검색에 쓰는 글만 줄인다(본문은 그대로): 메뉴 문서는 영양정보 숫자 행을 빼고, 추천·메뉴판 문서는 제목과 첫 줄만 쓴다. 목록 문서를 통째로 임베딩하면 메뉴 이름 수십 줄에 주제가 묻혀 "달콤한 음료 추천해 주세요"에 그 문서가 나오지 않았다 |
| STORE | FAISS `IndexFlatIP` (정규화 벡터의 내적 = 코사인 유사도) → `data/rag/index/` |
| RETRIEVE | ① 질문에 메뉴명(한글·영문·별칭)이 그대로 있으면 그 메뉴 문서를 먼저 ② 나머지는 임베딩 유사도 순 ③ 짧은 후속 발화("L로 주세요")에는 직전 대화에 나온 메뉴 문서를 최대 3개 더 붙인다 |
| 추가 검색 | 모델이 `search_knowledge` 도구로 직접 다시 검색한다 (복합 질의의 하위 질문마다) |

문서 종류 (HTI 의 RAG 문서 D1~D3):

- **D1 메뉴 문서** — `menu` 175 (이름·외국어 이름·설명·가격·옵션·영양·알레르기), `recommendation` 18, `category` 9. 외국어 이름은 번역한 값이다(`scripts/translate_menu.py`)
- **D2 옵션 문서** — `option` 14 (당도 단계별 뜻, 얼음량과 고를 수 없는 "얼음 없이", 토핑 설명·추가 요금, 사이즈 용량, HOT/ICE, 컵)
- **D3 이용 안내 문서** — `guide` 8 (키오스크 사용법, 결제 방법과 단말기 위치, 적립·할인·쿠폰, 교환권·금액권, 요청 사항 처리 방침, 직원 호출 방법, 알레르기 안내, 주문 방법), `policy` 6, `store` 1, `knowledge` 5
- **D4 실시간 상태** — 문서가 아니다. 품절·지금 장바구니·가격 계산 결과를 키오스크가 매 턴 `<실시간상태>`로 넘긴다

자세한 내용은 [data/README.md](data/README.md).

## 프롬프트와 OpenAI API

- **시스템 프롬프트** (`prompts.py`): 역할, 절대 하지 않는 것 9가지(HTI 의 G1~G9), 메뉴 안내·추천, 변경안과 확인, 결제 안내, 범위 밖 요청, 말투, few-shot 예시, 키오스크 설정(데이터에서 생성)
- **구획 태그**: `<실시간상태>` `<화면조작>` `<참고문서>` `<응답언어>` `<손님>` 으로 나눠, 손님 글에 지시문이 섞여도 지침으로 읽지 않게 한다
- **Function Calling** (`tools.py`)
  - 알아보기: `search_knowledge` `find_menus` `compare_menus` `menu_options` `calculate_price`
  - 변경안 올리기: `add_to_cart` `update_cart_item` `remove_cart_item` `add_request_note` `remove_request_note` `set_order_options` `undo_last_change`
  - 그 밖: `call_staff` `set_language`
- **Streaming**, **Embeddings**, **Moderation**

## 최종 HTI 대응

### 과업

| 상위 과업 | 하위 과업 → 구현 |
|---|---|
| 키오스크를 내게 맞추기 | **언어 고르기**: 시작 화면·상단의 언어 버튼(한/영/중/일). **내 언어로 입력하기**: 다른 언어로 치면 화면과 답변 언어가 따라 바뀐다. **큰 글씨·낮은 화면**: 시작 화면·상단 버튼 |
| 매장·포장 고르기 | 시작 화면의 두 버튼. 주문 내역 위에서 바꿀 수 있다 |
| 메뉴 찾기 | **카테고리별**: 메뉴판 탭. **베스트·시즌**: 매장 메뉴판과 같은 베스트(BEST SELLER)·신메뉴·시즌 탭과 배지. 카드마다 메뉴판처럼 '카페인 없음'·'ICE 전용' 표시. **추가 제안**: 담은 뒤 "담았어요"를 먼저 알리고 베스트 메뉴 3개 제안. **취향 말하고 추천받기**: `find_menus`·추천 문서. 맞는 메뉴가 없으면 어떤 조건을 빼면 무엇이 있는지 도구가 알려 준다. **예산·인원**: `find_menus(total_budget, people)` 가 예시 조합과 POS 합계를 함께 준다 |
| 메뉴 알아보기 | **설명·가격·칼로리·카페인**: 메뉴 상세 화면에 바로 표시. **물어보기**: [물어보기], [알레르기·재료 물어보기]. **품절 여부**: 메뉴판에 품절 표시, 실시간 반영. **비교해 묻기**: `compare_menus` + 화면의 비교표 |
| 메뉴 고르기 | **목록에서**: 메뉴 사진 누르기. **교환권으로**: [교환권 사용] → 바코드 찍기 → 그 메뉴가 담김. **이름 말해 고르기**: `add_to_cart` → 변경 확인 화면 |
| 음료 맞춤 설정하기 | 옵션 화면: 사이즈(L·J, 용량 표시)·온도·당도(단계별 뜻)·얼음(적게·보통·많이)·토핑·샷 추가·컵(매장컵·일회용컵·개인컵). **옵션 뜻 물어보기**: 옵션 문서. **한 문장으로 말하기**: 대화 또는 옵션 화면의 "옵션을 말로 입력하기". **가능 여부 묻기**: `menu_options` + 대안 제시 |
| 주문 목록 관리하기 | 주문 내역: 수량 ±, [옵션 변경], [삭제], [전체 취소]. **말로 바꾸기·여러 잔 한 번에**: 변경안 → 변경 확인 화면. **요청 사항 남기기**: 대화로 말하면 짧은 메모로 정리해 주문에 붙이고 직원 화면에 전달 |
| 결제하기 | 결제 화면 4단계. **할인·적립**: 앱·멤버십·쿠폰 바코드 찍기. **결제수단**: 카드 / 간편결제(휴대폰 갖다 대기, 결제 바코드) / 금액권. **돈 내기**: 카드 꽂기·빼기 등 단말기 조작. **다시 시도**: 승인 거절 시 [다시 시도]·[다른 결제수단]·[직원 호출] |
| 주문 결과 확인하기 | 결제 뒤 영수증 받을지 선택 → 주문번호 화면 → [영수증 가져가기] |
| 도움 받기 | **직원 부르기**: [직원 호출] 또는 대화 → 직원 화면에 표시. **사용법 물어보기**: [사용법] 버튼 또는 대화 → 이용 안내 문서 |
| 모든 화면 공통 | 상단의 [이전] · [처음으로] · [남은 시간 · 시간 연장], 각 창의 [닫기]. **고쳐 다시 말하기**: "아니 그거 말고" → `undo_last_change`, 변경 확인 화면의 [고쳐서 다시 말하기], [되돌리기] |

### 기능

| HTI 기능 | 구현 |
|---|---|
| L1 문장 이해 · L5 옵션 적용 · L8 말로 목록 수정 | 도구 인자로 메뉴·옵션·수량을 뽑아 변경안에 반영 (`add_to_cart`, `update_cart_item`, `remove_cart_item`) |
| L2 메뉴 추천 · L3 메뉴 답변 · L6 옵션 설명 · L10 사용법 안내 | RAG + `find_menus` |
| L4 메뉴 비교 | `compare_menus` → 답변 + 비교표 |
| L7 옵션 가능 판단 | `menu_options` 로 확인, 안 되면 가장 가까운 대안. 화면에 없는 값("얼음 없이")은 도구가 거절하고 대안을 알려 준다 |
| L9 다국어 응답 | 손님 언어 감지 → 화면·답변 언어 전환. 버튼 이름도 그 언어로 안내. 외국어 화면에서는 메뉴 이름·설명(`data/curated/menu_i18n.json`), 카테고리·맛·알레르기·영양 항목(`web/i18n.js` 의 `VOCAB`), 매장 이름까지 그 언어로 보여 준다. 답변도 메뉴판과 같은 이름을 쓰고("그 언어의 이름 (한글 이름)") 가격은 ₩ 로 쓴다 |
| L11 되묻기·정정 | 사이즈·온도가 빠지면 선택지 버튼, 이름이 애매하면 후보 제시, `undo_last_change`. 손님 말이 서로 부딪치면("아이스 아메리카노 따뜻하게 얼음 많이") 코드가 찾아 `<주의>`로 알리고, 한 음료에 대한 것이면 도구가 올리기를 거절해 되묻게 한다. 그 메뉴에서 고정이라 반영하지 못한 당도·얼음은 답변에 반드시 밝힌다. "첫 번째 걸로"는 실시간 상태의 '직전에 안내한 메뉴'로 가리고, 없으면 되묻는다. 이미 담긴 메뉴를 또 담으면 도구가 알려 줘 모델이 바로잡는다 |
| L12 요청 메모 | `add_request_note` (60자, 주문당 5개) |
| U1~U6, U8 | 메뉴판, 옵션 화면, 주문 내역, 접근성 설정, 시작 화면, 추가 제안 창, 공통 이동 (`web/app.js`) |
| U7 변경 확인 화면 | 모델이 올린 추가·변경·삭제·메모를 바뀌는 항목과 금액(전 → 후)으로 보여 준다. [확인] · [취소] · [고쳐서 다시 말하기] · [옵션 직접 고치기] |
| P1 결제 단말기 · P2 바코드 리더 | `pos.py` + `web/pay.js` 의 시연용 단말기. 화면에 단말기 그림을 그려 카드 투입구·바코드 리더 위치를 강조한다 |
| P3 POS 계산 | `order.py` 의 합계·교환권·쿠폰·제휴 할인·금액권 차감, 결제 실패 처리 |
| P4 주문번호·영수증 | 결제 화면 마지막 단계 |
| S1 직원 전달 | `staff.py` + 직원 화면(`/staff`): 직원 호출, 결제된 주문과 요청 메모 |

### LLM 이 하면 안 되는 것

| | 어떻게 지키나 |
|---|---|
| G1 지어내기 금지 | 프롬프트. 금액·옵션·품절은 도구와 실시간 상태에서만 온다 |
| G2 알레르기 단정 금지 | 프롬프트 + 알레르기 안내 문서. **코드**: 손님이 알레르기를 물었는데 답변에 교차 오염·직원 확인 안내가 없으면 정해 둔 문구를 붙인다 |
| G3 품절 추천 금지 | **코드**: `find_menus` 가 품절을 빼고, 담으려 하면 거절한다. 검색 문서에 "지금 품절" 표시 |
| G4 안 되는 옵션 금지 | **코드**: 메뉴별 규칙으로 검증해 거절한다 |
| G5 금액 계산 금지 | 프롬프트 + `calculate_price` 도구(예산을 인원으로 나누는 것도 코드가 한다). 화면의 금액은 모두 POS 값. **코드**: 답변의 금액이 모델이 받은 글 어디에도 없으면 한 번 다시 쓰게 하고, 그래도 남으면 확인 안내를 붙인다 |
| G6 확인 없이 변경 금지 | **코드**: 도구는 변경안만 고친다. [확인]은 화면 버튼으로만 누를 수 있다. 말로 한 "네"는 코드가 받아 [확인]을 안내한다. 품절 메뉴 대신 다른 메뉴를 올리지 말라고 도구가 알려 준다 |
| G7 결제 개입 금지 | **코드**: 결제·할인·적립 도구가 없다. 결제 화면이 열려 있으면 변경안도 올릴 수 없다 |
| G8 주문 밖 대화·개인정보 금지 | 프롬프트. 적립·할인은 바코드로만 한다(전화번호를 받는 곳이 없다) |
| G9 요청 약속 금지 | 프롬프트 + 화면의 "직원에게 전달만 돼요" 문구. **코드**: 메모를 올린 답변에 "어려울 수 있다"는 말이 없으면 붙인다 |

### HTI 에서도 그대로 남는 막힘

적립은 앱 바코드가 있어야 하고, 바코드가 안 읽히거나 결제가 안 되면 결국 직원이 필요하며, 음성 안내가 없다.
대신 바코드 인식 실패와 승인 거절을 시연할 수 있게 해 두었고, 그 화면에 [직원 호출]을 두었다. 카드 투입구 위치는 결제 화면의 단말기 그림과 대화("카드는 어디에 꽂아요?")로 안내한다.

## 알려진 한계

- **결제·바코드·단말기·영수증·직원 호출은 시뮬레이션이다.** 바코드 코드와 쿠폰 내용(2,000원 할인, 무료 음료)은 시연용으로 지어낸 값이다(`data/curated/barcodes.json`).
- **기기 위치, 컵 규칙, 당도 단계 설명, 요청 사항 방침, 시간 제한은 가정값이다.** 매장 키오스크를 확인하지 못했다. `data/curated/` 에 `verified: false` 로 표시했다.
- **품절은 서버 메모리에만 있다.** 서버를 다시 켜면 `data/curated/stock.json` 의 초깃값(초코멜로 스무디)으로 돌아간다.
- **직원 화면에는 로그인이 없다.** 시연용이다.
- **디저트·푸드는 키오스크로 주문하지 않는다.** 키오스크 화면 사진에 가격이 있는 12종만 메뉴판에 보여 주고 카운터 주문으로 안내한다.
- **매장 메뉴판·키오스크 화면 사진에 있는 메뉴만 판다** (음료 120종 중 76종). 저당 시리즈, 지난 시즌 메뉴, 1리터 배달 메뉴, MD 는 숨긴다.
- 가격은 매장 판매가이고 토핑은 J 사이즈가 200원 더 비싸다. 당도·얼음 조절 여부를 모르던 7종은 조절 가능으로 두었다. [data/README.md](data/README.md) 참고.
- 메뉴의 외국어 이름과 설명(영어·중국어·일본어)은 모델로 번역한 값이다. 영문명의 눈에 띄는 오역만 고쳤고 전체를 검수하지는 않았다. 화면 버튼으로 담을 때 서버가 돌려주는 안내("당도 조절 여부 미확인" 등)와 직원에게 가는 요청 메모는 한국어다.
- 대화와 주문은 서버 메모리에만 있다. 서버를 다시 켜면 사라진다.
- G1·G8 은 프롬프트로만 지키는 규칙이라 모델이 어길 가능성이 남아 있다. G2·G5·G9 는 코드가 답변을 다시 확인하지만 정해 둔 패턴만 잡는다(금액 검증은 "원"이 붙은 숫자가 근거에 있는지만 본다). G3·G4·G6·G7 은 코드로 막는다.
- 모델의 행동은 매번 조금씩 다르다. `scripts/eval_scenarios.py` 로 과업별 통과 횟수를 재지만, 거기 없는 말에는 다르게 답할 수 있다.
- 추천 조건 가운데 맛 태그는 메뉴 이름과 설명에서 규칙으로 뽑은 값이고, 영양정보가 당도 0% 기준이라 "덜 단"은 당도를 낮출 수 있는지와 당도 0% 의 당류로만 가린다.
- 답변 한 번에 2~4초가 걸린다(서버를 켠 직후의 첫 답변도 미리 데워 두어 비슷하다).
- `RAG_MIN_SCORE`(유사도 하한)는 꺼져 있다. `scripts/eval_retrieval.py` 로 점수를 본 뒤 정한다.
