# cafe-Kiosk-chatbot

공차(시흥배곧점) 메뉴로 만든 **카페 키오스크 자연어 인터페이스**. 손님이 채팅으로 메뉴를 묻고, 추천받고, 주문·결제까지 한다.
RAG(검색 증강 생성)와 OpenAI Function Calling 으로 동작한다.

## 실행

Python 3.10 이상이 필요하다.

```bash
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env          # .env 를 열어 OPENAI_API_KEY 를 넣는다

python scripts/build_index.py # 문서 임베딩 → FAISS 인덱스 (처음 한 번, 생략해도 서버가 알아서 만든다)
python -m app                 # http://localhost:8000
```

`.env` 를 고치거나 코드를 바꾼 뒤에는 서버를 껐다 켜야 반영된다 (Ctrl+C 후 다시 `python -m app`).

주문은 두 가지 방법으로 한다. 둘 다 같은 장바구니를 쓴다.

- **대화로**: "아메리카노 아이스 L 하나 주세요"
- **화면으로**: 메뉴판에서 상품을 누르면 수량·사이즈·HOT/ICE·당도·얼음·토핑을 고르는 창이 뜬다. 고르는 대로 금액이 바뀌고, **담기**를 누르면 주문 내역에 들어간다. 주문 내역의 **옵션 변경**으로 다시 고칠 수 있다.

화면 오른쪽 위의 **근거 보기**를 켜면 답변마다 검색된 문서(유사도)와 호출된 도구가 보인다. 시연할 때 켜 두면 좋다.

```bash
python -m pytest                    # 테스트 (API 키 없이 돈다)
python scripts/eval_retrieval.py    # HTI 질문별로 기대한 문서가 검색되는지 확인 (API 키 필요)
```

## 구조

```
브라우저 (web/)                      서버 (app/)
┌───────────────────────────┐       ┌────────────────────────────────────────────────┐
│ 메뉴판 │ 대화 │ 주문 내역 │ ◀SSE▶ │ server.py     API · 화면 제공                  │
└───────────────────────────┘       │ chatbot/      agent.py   한 턴의 흐름          │
                                    │               prompts.py 시스템 프롬프트·문맥  │
                                    │               tools.py   Function Calling 도구 │
                                    │ rag/          store.py   임베딩 · FAISS 저장   │
                                    │               retriever.py 하이브리드 검색     │
                                    │ catalog.py    메뉴판 조회 · 메뉴명 찾기        │
                                    │ order.py      장바구니 · 가격 · 옵션 검증      │
                                    └────────────────────────────────────────────────┘
                                         │ OpenAI API                 │ data/
                                         ▼                            ▼
                         Embeddings · Chat Completions      kiosk/*.json (구조화 데이터)
                         (도구 호출, 스트리밍) · Moderation  rag/documents.jsonl (검색 문서)
```

**손님이 한마디 하면 (agent.py)**

1. **검색**: 손님의 말을 임베딩해 문서 6개를 찾는다. 동시에 Moderation 으로 유해한 입력인지 확인한다. 손님이 쓴 언어가 화면 언어와 다르면 언어도 바꾼다.
2. **증강**: 시스템 프롬프트 + 최근 대화 + `<주문상태>` `<참고문서>` `<손님>` 을 묶어 모델에게 보낸다.
3. **생성**: 모델이 답을 쓰거나 도구를 부른다. 도구 결과를 돌려주고 다시 묻기를 반복한다(최대 5번).
4. 답변은 글자가 나오는 대로 화면에 흘려 보내고(SSE), 답변에 나온 메뉴 카드와 빠른 답변 버튼을 붙인다.

**설계 원칙: 말은 모델이, 계산은 코드가.** 모델에게 맡기면 틀릴 수 있는 일은 코드가 한다.

- 가격 합계, 할인, 옵션이 되는지 안 되는지: `order.py` 가 `data/kiosk/menu.json` 을 보고 정한다.
- 조건이 여러 개인 추천("카페인도 없고 우유도 없는"): `find_menus` 도구가 메뉴판 데이터에서 직접 고른다. 모델이 추천 목록 두 개를 눈으로 겹쳐 보게 했더니 카페인이 든 메뉴를 섞어 답했다.
- 결제 전 확인: `checkout` 은 적립·할인 여부를 묻지 않았으면 거절하고, 첫 호출에서는 결제하지 않고 최종 주문 내용을 돌려준다. 손님이 확인한 뒤 같은 내용으로 다시 호출해야 결제된다.

## RAG

| 단계 | 구현 |
|---|---|
| LOAD | `data/rag/documents.jsonl` 232개 문서 (`scripts/build_dataset.py` 가 생성) |
| SPLIT | 따로 하지 않는다. 문서를 만들 때 이미 "메뉴 1개 = 문서 1개"로 나눴다 |
| EMBED | `text-embedding-3-small`. 검색에 쓰는 글만 줄인다(본문은 그대로): 메뉴 문서는 영양정보 숫자 행을 빼고, 추천·메뉴판 문서는 제목과 첫 줄만 쓴다 |
| STORE | FAISS `IndexFlatIP` (정규화 벡터의 내적 = 코사인 유사도) → `data/rag/index/` |
| RETRIEVE | ① 질문에 메뉴명이 그대로 있으면 그 메뉴 문서를 먼저 ② 나머지는 임베딩 유사도 순 ③ 짧은 후속 발화("L로 주세요")에는 직전 대화에 나온 메뉴 문서를 최대 3개 더 붙인다 |
| 추가 검색 | 모델이 `search_knowledge` 도구로 직접 다시 검색한다 (복합 질의의 하위 질문마다) |

`scripts/eval_retrieval.py` 의 HTI 질문 26개 기준으로, 추천·메뉴판 문서를 통째로 임베딩했을 때는 20개만 찾았고
(메뉴 이름 수십 줄에 주제가 묻혀 "달콤한 음료 추천해 주세요"에 달콤한 음료 문서가 안 나왔다) 제목과 첫 줄만 임베딩하니 26개를 모두 찾았다.

문서 종류: `menu` 175 (설명·가격·옵션·영양·알레르기) / `recommendation` 21 (맛별·인기·무카페인·저칼로리·신메뉴·디저트 등) /
`option` 13 / `category` 9 / `policy` 6 / `knowledge` 5 / `guide` 2 / `store` 1. 자세한 내용은 [data/README.md](data/README.md).

## 프롬프트와 OpenAI API

- **시스템 프롬프트** (`prompts.py`): 역할 지정, 근거 기반 답변 규칙, 질문 유형별 대응, 주문 절차, 범위 밖 요청 대응, 말투·형식, few-shot 예시, 키오스크 설정(데이터에서 생성)
- **구획 태그**: `<주문상태>` `<참고문서>` `<손님>` 으로 나눠, 손님 글에 지시문이 섞여도 지침으로 읽지 않게 한다
- **Function Calling** (`tools.py`): `search_knowledge` `find_menus` `add_to_cart` `update_cart_item` `remove_cart_item` `set_order_options` `checkout` `call_staff` `set_language`
- **Streaming**, **Embeddings**, **Moderation**

## 과제 요구사항 대응

| 요구사항 | 처리 방식 |
|---|---|
| 메뉴 정보 제공 ("아메리카노 중 사이즈 얼마인가요?") | 메뉴명 일치 검색으로 메뉴 문서를 찾아 사이즈별 가격 안내. 없는 사이즈는 L/J 를 안내 |
| 음료 추천 ("달콤한 음료 추천해 주세요") | 추천 문서(맛·카페인·칼로리·인기 등) 검색 → 2~3개를 이유·가격과 함께 제안. 조건이 여러 개면 `find_menus` |
| 옵션 ("라떼에 바닐라 시럽 추가할 수 있나요?") | 옵션 문서 검색. 없는 옵션은 없다고 알리고 대안(당도, 토핑, 비슷한 메뉴) 안내 |
| 복합 질의 | 요청을 나눠 각각 답하고, 필요하면 하위 질문마다 `search_knowledge` 를 따로 호출 |
| 이상한·무관한 질문 | 프롬프트 규칙 + few-shot 으로 정중히 사양하고 주문으로 유도. 유해 입력은 Moderation 으로 차단 |

## HTI 대응

| HTI | 구현 |
|---|---|
| 1 언어 선택 | 상단 언어 버튼(한/영/중/일). 손님이 다른 언어로 말하면 자동으로 바뀐다 |
| 2.1 직원 호출 | 상단 버튼, `call_staff` |
| 2.2 이용시간 / 2.3 이용 방법 | `store` · `guide` 문서, 시스템 프롬프트의 주문 순서 |
| 3.1 신메뉴·추천 / 3.2 가격 / 3.3 카테고리 | 메뉴판 탭(추천·신메뉴·음료 6종·디저트·기타), `recommendation` · `category` · `menu` 문서 |
| 4.1 취향 / 4.2 곁들임 / 4.3 계절·인기 추천 | `recommend:flavor-*` 등 / `recommend:dessert` / `recommend:season` · `popular` · `best` |
| 5.1 상세 정보 | 상품 창(설명·가격·영양·알레르기), `menu` 문서 |
| 5.2 옵션 (ICE/HOT, 샷, 텀블러, 당도·얼음, 펄, 사이즈) | 상품 창의 옵션 선택, 또는 대화(`add_to_cart` · `update_cart_item`). 둘 다 메뉴별 규칙으로 검증한다. 시럽 추가(5.2.3)는 공차에 없어 대안을 안내 |
| 5.3 매장/포장, 빨대·캐리어 | `set_order_options`, 주문 내역의 매장/포장 버튼 |
| 6 장바구니 (수량, 수정·취소) | 대화(`update_cart_item` · `remove_cart_item`) 또는 주문 내역의 +/− · 옵션 변경 · 삭제 |
| 7 결제 (금액·수량·옵션 확인, 적립·할인, 결제 수단) | 매장/포장 → 적립·할인(`set_order_options`: SKT/KT 10%, 스탬프) → 결제 수단 → `checkout` 이 돌려준 최종 주문 내용을 손님이 확인 → 결제 |
| 8 주문번호, 영수증 | 결제 완료 팝업에 주문번호와 영수증 출력 여부 표시 |

## 알려진 한계

- **디저트·푸드·MD 는 가격 데이터가 없어 주문할 수 없다.** 설명만 안내하고 직원 문의로 넘긴다.
- 가격은 배달앱 판매가이고, 당도·얼음 조절 여부를 모르는 메뉴가 21종 있다 (요청은 받되 "매장 확인 필요"로 안내). [data/README.md](data/README.md) 참고.
- 결제 수단, 텀블러, 포장 옵션은 실제 매장 키오스크를 확인하지 못한 가정값이다. 결제·직원 호출·영수증은 시뮬레이션이다.
- 메뉴명은 한글만 있다. 다른 언어에서는 모델이 괄호로 번역을 덧붙인다.
- 대화와 주문은 서버 메모리에만 있다. 서버를 다시 켜면 사라진다.
- `RAG_MIN_SCORE`(유사도 하한)는 꺼져 있다. `scripts/eval_retrieval.py` 로 점수를 본 뒤 정한다.
